# SIH 2026 — Quantum Machine Learning for Early Disease Detection

## Round 1 — Setup and Reproduction Guide

This repository contains the Round 1 implementation of a hybrid quantum-classical machine learning pipeline for binary disease classification.

The current implementation supports:

* **WDBC (Wisconsin Diagnostic Breast Cancer)**
* **UCI Heart Disease**

The same hybrid quantum-classical model can be trained on either dataset through the shared preprocessing and evaluation pipeline.

---

# 1. Requirements

## Hardware

The current implementation uses PennyLane's `default.qubit` simulator, so a quantum computer is **not required**.

A normal laptop/desktop is sufficient.

Recommended:

* 8 GB RAM or more
* Modern multi-core CPU
* Internet connection for initial package installation

GPU acceleration is not required for the current Round 1 implementation.

---

# 2. Install Python

The project is intended to use **Python 3.12**.

Check whether Python is already installed:

```powershell
python --version
```

Expected:

```text
Python 3.12.x
```

If Python is not installed, install Python 3.12 from the official Python website.

After installation, verify:

```powershell
python --version
```

### Important — Windows Python launcher

Windows may have multiple Python versions installed.

Check:

```powershell
py --version
```

and:

```powershell
python --version
```

For this project, use the `python` command that points to the Python 3.12 installation.

Do not assume that `py` and `python` point to the same interpreter.

# 10. Test the preprocessing pipeline

From the project root:

```powershell
python -m preprocessing.preprocessing
```

This runs the preprocessing pipeline for both datasets.

The expected WDBC dimensions are:

```text
Samples : 569
Features: 30

X_train: (455, 30)
X_test : (114, 30)

Quantum-ready data:
X_train: torch.Size([455, 4])
X_test : torch.Size([114, 4])
```

The expected Heart Disease dimensions are:

```text
Samples : 303
Features: 13

X_train: (242, 13)
X_test : (61, 13)

Quantum-ready data:
X_train: torch.Size([242, 4])
X_test : torch.Size([61, 4])
```

The preprocessing pipeline performs:

```text
Raw dataset
     ↓
Train/Test split
     ↓
StandardScaler
     ↓
PCA → 4 components
     ↓
MinMaxScaler → [0, π]
     ↓
PyTorch float32 tensors
```

# 12. Hybrid model architecture

The current hybrid model uses:

```text
4 input features
       ↓
AngleEmbedding
       ↓
4-qubit quantum circuit
       ↓
StronglyEntanglingLayers
       ↓
4 Pauli-Z expectation values
       ↓
Linear(4 → 1)
       ↓
Binary classification
```

Configuration:

```text
Qubits:       4
Layers:       3
Batch size:   16
Epochs:       15
Optimizer:    Adam
Loss:         BCEWithLogitsLoss
```

During inference:

```text
logit
  ↓
sigmoid
  ↓
probability
  ↓
0.5 threshold
  ↓
binary prediction
```

# 14. Evaluation

The shared evaluator is located at:

```text
evaluation/evaluate.py
```

It reports:

* Accuracy
* Sensitivity
* Specificity
* Precision
* Recall
* F1-score
* ROC-AUC
* Confusion matrix

ROC-AUC requires the model's continuous probability/score output to be passed to:

```python
y_prob
```

The evaluator also handles different dataset label conventions through:

```python
disease_label
```

and:

```python
class_names
```

The current generalized preprocessing convention is:

```text
0 = No Disease
1 = Disease
```

with dataset-specific display names.

# 15. Current Round 1 WDBC baseline

The generalized hybrid pipeline currently produces approximately:

```text
Accuracy:       94.74%
Sensitivity:    85.71%
Specificity:    100.00%
ROC-AUC:        0.9970
```

on the fixed WDBC test split.

The split uses:

```text
test_size = 0.20
random_state = 42
stratify = y
```

These results should be treated as the current Round 1 baseline for the generalized hybrid pipeline.

Training and inference times are hardware-dependent and should not be expected to exactly match another machine.

# 19. Important reproducibility notes

The project uses:

```python
torch.manual_seed(0)
np.random.seed(0)
```

and:

```python
random_state=42
```

for the train/test split.

This makes the experiment substantially more reproducible.

However, exact execution time can vary between machines.

Do not compare training time across machines without considering:

* CPU
* Python version
* PyTorch version
* PennyLane version
* operating system
* system load

# 20. Common problems

## `.venv\Scripts` does not exist

Make sure the environment was created using Windows Python:

```powershell
python -m venv .venv
```

Then check:

```powershell
dir .venv
```

A Windows virtual environment should contain:

```text
Scripts/
```

---

## `ModuleNotFoundError: No module named 'evaluation'`

Run package modules from the project root:

```powershell
python -m integration.run_hybrid
```

rather than:

```powershell
python integration\run_hybrid.py
```

Make sure:

```text
evaluation/__init__.py
integration/__init__.py
```

exist.

---

## Wrong Python version

Check:

```powershell
python --version
```

and:

```powershell
where.exe python
```

Make sure the active interpreter is the one inside:

```text
.venv\Scripts\python.exe
```

Verify:

```text
data/
├── wdbc.data
└── heart.csv
```

and run the commands from the project root:
